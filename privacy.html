Privacy

Project Unveiled uses limited first-party readership analytics. The purpose is to understand which pages are being read, which campaigns bring visitors, whether readers move between chapters, and how often support links are clicked.

What is recorded

Page paths and titles, anonymous browser-tab session identifiers, campaign labels such as utm_source, referring website names (not the referring page path), page views, 30-second engagement, scroll-depth thresholds, chapter-navigation activity, whether chapter search was used (not the search text), and the destination and visible label of measured on-site controls such as Journey, share, support, store, and PayPal links. On the 7-Day Journey path, analytics also counts signup-button selections and anonymous visits to the check-email and confirmed-reader pages. Names and email addresses entered in the signup form are not sent to analytics. Link destinations exclude query strings, fragments, and prefilled message bodies.

What is not recorded

No visitor or request IP address is stored with analytics events, and IP-literal referrers and external link destinations are rejected. No advertising profile is created. No cross-site tracking cookie is used. Search text and utm_term values are not collected. The analytics do not reveal whether a PayPal payment was completed or disclose payment information. A secret-protected address digest is used only to prevent abusive collection and login attempts; entries older than two days are discarded when rate controls next run.

Your browser controls

The tracker respects Do Not Track and Global Privacy Control signals. Its anonymous session identifier is stored only in the current browser tab and ends when that tab session ends.

Purpose and retention

The information is used to improve Project Unveiled, understand readership, and evaluate outreach. Analytics files are stored privately outside the public website directory. Files older than 100 days are retired on the next analytics collection or authenticated dashboard access, and may be deleted sooner when no longer useful.

Free Truth Trial

When you choose Run Free Truth Trial, the question and any optional context are sent to the configured OpenAI Responses API for the one web-backed synthesis you requested. The application sends store: false, asking the API not to store the response as a retrievable provider response. Project Unveiled does not keep the raw question or context in its local operational logs. A successful-request record retains secret-protected request-address and question digests, the question length, a protected provider-response identifier, the model identifier, and bounded token, search, and source counts. A separate failure-diagnostic record can retain HTTP status, safe error and cURL codes, and secret-protected digests and lengths of provider or transport messages, but not the raw messages.

Those local operational records are retained for up to 180 days and may be deleted sooner. Expired records are retired during the next Free Truth Trial or deployment migration. The generated result is returned to your browser, so consider whether the question itself contains personal information before submitting it.

Private Truth-Worthy questions and challenges

A private question submission can include its topic, question, optional context, and optional name and email address. An evidence challenge can include its case, challenge type, argument, optional source, and optional name and email address. Project Unveiled uses this information only for private owner review, follow-up when requested, and deciding whether evidence warrants an investigation or correction.

The submitted record is stored outside the public website and is not displayed publicly or sold. The raw request address is not placed in the record; a secret-protected digest derived from the request address is stored only for abuse prevention.

If the owner chooses to investigate a submitted question in the private Daily Desk, its question and context are sent to the configured OpenAI Responses API for that investigation. The application sends store: false, asking the API not to store the response as a retrievable provider response. The resulting research draft and its source and usage metadata remain in private owner-only storage under the same question-retention deadline. The application blocks that private-question draft from publication; publishing related material would require separately authored nonprivate work.

The configured retention window is never more than 180 days from submission, and a record may be deleted sooner. Expired data is removed lazily when a relevant intake or private Daily Desk maintenance or access operation next runs, so physical removal can occur after the deadline when none of those operations has run. To ask a privacy question or request early deletion of a question or challenge, email thebobsomest1@gmail.com and include enough detail to identify the submission.
