# OOIS Android preview

This APK is a device-only test build, not a Google Play release. Its app ID is `com.bobsome1.oois.preview` and its label is **OOIS Field Preview**. It stores records separately from a browser notebook and any future production Android app. Cloud upload and Gemini analysis are disabled in this build.

## Install and try

1. Download and open `OOIS-Field-Mapper-Preview.apk` on your Android phone. If Android asks, allow installation from the app used to open this file for this installation. Keep Play Protect enabled. This preview requires Android 7 or newer.
2. Start **OOIS Field Preview**. Tap a spot on the map and enter a test record with a photo and notes. Save it, close the app, then reopen it and confirm the record and photo remain.
3. Tap **Capture GPS** and grant location permission while using the app. Confirm it opens a record near your actual location. Declining permission should show an error without losing records.
4. Edit the test record. Add another nearby record and confirm it appears as a comparison candidate. The local checklist does not analyze pictures or authenticate finds.
5. Export a backup and save it through Android's share sheet. Import it into a browser notebook to confirm the record and photo transfer. Keep this backup outside the app before uninstalling or trying another build.
6. Turn on airplane mode, reopen the app, and save another record. The notebook works offline; new map tiles do not.
7. Check that the phone's status bar, camera cutout, keyboard and gesture bar do not cover buttons. Test portrait and landscape.

The CI job compiles the APK and runs Android lint. These checks do not prove GPS, photo selection, file sharing or layout work on a physical phone; the steps above are still required.

Preview builds use a temporary debug signature generated by the build runner. A later preview may require uninstalling the old one before installation. **Uninstalling erases that app's notebook: export first.** Debug signatures are not owner release keys, and this package cannot be submitted as a Play release.

## Cloud activation and production release

The selected route is a dedicated **OOIS Field Mapper** Firebase project, `bobsome1@bobsome1.com` as the private primary owner, and Google Play internal testing first. The actual Firebase project ID is safe to share; passwords, API secrets and signing keys are not. An administrator must configure billing safeguards, the accounts, private rules, Storage CORS and Gemini secret using the README and `PLAY-INTERNAL-TEST.md`. Production signing credentials, a signed release bundle and physical-device testing are separate release steps.

## Play internal-test evidence

After the dedicated Firebase project passes live verification and the owner approves the first Play upload, install the production package from the Play internal-test link rather than sideloading it. Use only synthetic records for this pass.

1. Record the app version, Android version and Galaxy A17 model/build.
2. Confirm the installed package is **OOIS Field Mapper**, not **OOIS Field Preview**, and that Play Protect reports no issue.
3. Repeat all seven device checks above. Also deny location once before granting it, background and resume the app during an unsaved entry, rotate while the editor and Cloud settings dialogs are open, and confirm no field or photo is silently lost.
4. Sign in with the private owner account. Save, import and delete one synthetic cloud record with a photo. Confirm the non-owner denial test and one authorized Gemini image test already have a passing sanitized receipt.
5. Export the local notebook, uninstall the internal build, reinstall it from Play, and confirm the app starts empty. Restore the export and confirm the record/photo return. This proves the backup path rather than assuming Android app-data restoration.
6. Review Play's pre-launch report for crashes, ANRs, accessibility, security and device-compatibility warnings. Treat an unexplained warning as a blocker.
7. Save screenshots and a short result note for each check. Do not include real coordinates, private photos, passwords, Firebase secrets or signing material in the evidence package.

Internal testing is the current milestone; no public release is authorized.
